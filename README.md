# 제4차 슈퍼로봇대전 S — 한글 패치

PlayStation 『第4次スーパーロボット大戦S』(SLPS-00196, Japan Rev 1) 한글화 프로젝트입니다.
패치 파일과, 그걸 만드는 데 쓴 역공학 도구·기술 문서를 담았습니다.

**원본 디스크 이미지는 포함하지 않습니다.** 직접 준비하셔야 합니다.

## 지금 상태 (v0.99N)

| 항목 | 값 |
|---|---:|
| 시나리오 대사 (M_BANKS) | 8,990 / 9,070 레코드 (99.1%) |
| 전투 대사 (M_BANKB) | 1,900 / 1,918 레코드 (99.1%) |
| 표 슬롯 중 한글을 읽는 것 | 11,022 / 14,336 |
| 스테이지 승리 조건 | 80 / 80 |
| 가라오케 가사 | 124 / 124 |
| 폰트에 새로 그린 한글 | 1,246자 |

화면에 나오는 일본어 대사는 남아 있지 않습니다. 미번역으로 남은 80건은 전부
포인터 표·애니메이션 데이터가 글자로 읽힌 것이라 화면에 뜨지 않습니다.

바꿀 수 없는 것: 타이틀 메뉴와 브리핑 화면의 「승리 조건」·「패배 조건」 **라벨**은
문자열이 아니라 그림입니다. (조건 내용 자체는 한글입니다.)

## 설치

`dist/` 의 xdelta 를 원본 Track 1 에 적용합니다. 자세한 절차와 해시는
[`dist/README.txt`](dist/README.txt) 에 있습니다.

```
xdelta3 -d -s "Dai-4-Ji Super Robot Taisen S (Japan) (Rev 1) (Track 1).bin" \
           Dai-4-Ji_SRW_S_KR_v0.99N.xdelta \
           "Track 1 (patched).bin"
```

원본 Track 1 SHA-1 `39241b033cd8368713a30cf5b1a1e5d47fb3d353`
→ 패치 후 `5c38fa4e49e014d58ce90ff6ce3c986280ae36e7`

Track 2/3 과 `.cue` 는 건드리지 않습니다.

## 이 게임에서 배운 것

한글화하면서 부딪힌 구조들입니다. 자세한 내용은 `docs/` 에 있습니다.

**같은 데이터가 여러 곳에 있다.** 전투 대사는 디스크에 **세 벌** 있습니다 —
`BTT/M_BANKB.LZB`, STAYDAT 안의 전투 풀, 그리고 `BTT/C_BEFCT.BIN` 꼬리에
**압축된 채** 박혀 있던 세 번째 사본입니다. 전투는 첫 번째를, 맵 대화는 세 번째를
읽습니다. 두 벌만 고쳤을 때는 화면 절반만 한글로 나왔습니다. 폰트도 STAYDAT 과
C_DEMOG 두 벌입니다.

**같은 파일이 RAM 에 두 벌 올라오고, 레코드 id 가 어느 벌을 볼지 정한다.**
전투 대사 블롭 `M_BANKB` 는 BATTLE 오버레이 안에 한 벌, LZB 해제본으로 또 한 벌
올라옵니다. 레코드 id 의 **비트 15** 가 어느 벌을 읽을지 고릅니다. 오버레이 뒤에
빈자리를 뚫어 무기 이름을 되살렸는데, 같은 자리에 화자 이름을 놓으니 잡글자가
떴습니다 — 화자 이름은 다른 벌로 읽히고 거기엔 그 자리가 없었습니다. 사본을
세는 것만으로는 부족하고, **어느 사본이 언제 읽히는지**까지 봐야 합니다.

**슬롯도 점프도 안 가리키는 레코드가 있다.**
같은 블롭에 454개 레코드가 `키` 접두를 달고 끊김 없이 이어진 구간이 있습니다.
게임은 그 안으로 점프한 뒤 **키를 훑어** 원하는 줄을 찾습니다. 포인터가 없으니
"아무도 안 가리키는 자리" 로 보이지만, 한 바이트만 밀려도 화면이 깨집니다.
게다가 그 구간의 첫 레코드는 앞 레코드와 종단을 공유해서, 이름을 늘리려고 "꼬리
대사" 를 줄이면 실은 그 첫 레코드를 줄이게 됩니다. 두 판(v0.99e/f)을 이걸로
날렸습니다. 지금은 게이트가 (레코드 수, 키 순서, 각 시작 오프셋)을 원본과 대조합니다.

**포인터가 레코드 중간을 가리킨다.** 게임은 같은 대사를 화자 이름만 떼고 재사용하는데,
그 재사용이 문장 중간 바이트를 가리키는 포인터로 되어 있습니다. 번역하면 그 포인터가
읽는 내용이 달라집니다. 원문의 `「`·문단·줄바꿈 경계를 역문의 같은 자리로 이어 붙여
해결했습니다 ([`tools/mb_alias.py`](tools/mb_alias.py)).

**고정 칸은 원문보다 짧아야 한다.** 이름 칸은 역문 바이트가 원문 바이트보다
**짧아야** 합니다 — 같기만 해도 깨집니다. 복사기가 원문 길이만큼만 퍼 오기 때문에,
역문이 짧을 때만 종결자가 복사 범위 안에 들어옵니다. 원문이 2바이트인 항목은
한글 최소가 2바이트라 아예 번역이 불가능합니다.

**한도는 글자 수가 아니라 바이트, 또는 픽셀이다.** 한글은 2바이트, 일본어 반각 가나는
1바이트입니다. 고정 칸은 바이트로 잘리고, 화면 폭은 바이트 × 8 픽셀입니다.
가라오케 가사 한도가 26바이트인 것도 여기서 나왔습니다.

**공간은 옮겨서 만든다.** 가사가 들어갈 자리가 없어서, D_NAMES 뒤에 있던 상주 blob
`D_DEDMES`(1,166 B)를 잔재 구간으로 옮기고 슬롯을 53,248 → 55,296 B 로 넓혔습니다.
blob 의 RAM 주소가 코드가 아니라 MAP 오버레이의 **주소표**에 들어 있어서 u32 하나만
바꾸면 되는 구조였습니다. 파일 크기는 그대로입니다
([`tools/relocate_dedmes.py`](tools/relocate_dedmes.py)).

**압축기를 다시 썼다.** 게임의 LZB 를 그대로 재압축하면 원본보다 3.5% 커져서 파일이
자리에 안 들어갔습니다. 최적 파싱(DP)과 길이 2 매치를 넣어 원본의 0.98~0.99배로
줄였습니다 ([`tools/lzb_encode.py`](tools/lzb_encode.py)).

**자리가 없으면 안 읽히는 자리를 찾는다.** 전투 대사 블롭은 오버레이 이미지 한가운데
빈틈없이 박혀 있어 못 늘립니다. 그런데 뱅크 표 슬롯이 u16 이라 블롭 시작에서 65,535 까지
가리킬 수 있고, 블롭 뒤는 오버레이의 다른 구간입니다. 실기 읽기 브레이크포인트를
512 B 씩 43 조각에 걸어 **전투 중 한 번도 안 읽히는 것**을 확인하고 9,670 B 를 열었습니다
([`tools/build_battle_ko.py`](tools/build_battle_ko.py)). 잘려 있던 무기 이름 26종이
온전해졌습니다.

**화면의 출처는 브레이크포인트보다 찔러 보는 게 빠르다.** 전투 화자 이름이 어디서
오는지 찾느라 읽기 브레이크포인트를 일곱 번 걸었지만 매번 압축 해제기만 잡혔습니다.
그 바이트를 **실행 중에 덮어쓰자** 화면이 즉시 바뀌면서 출처가 확정됐습니다. 브레이크
포인트는 "누가 읽는가"를 묻고, 찌르기는 "이게 그 데이터인가"를 묻습니다. 후자가 답하기
훨씬 쉽고 대개 그것만 알면 충분합니다.

**이름 옆에 상대 점프가 숨어 있다.** 이름표처럼 보이던 것은 사실
**[이름 글자][공통 대사로 점프]** 가 번갈아 놓인 스크립트였습니다. `FC` 의 보조 테이블
인덱스 6·7 이 `대상 = (s16 주소) + s16` 인 상대 점프이고, 이름을 늘리면 뒤 점프가 밀리는데
s16 은 그대로라 엉뚱한 데 착지합니다. **늘린 만큼 s16 을 빼 주면** 코드 훅 없이 풀립니다
([`tools/mbankb_jumpfix.py`](tools/mbankb_jumpfix.py)). 진입점은 뱅크 표의 u16 슬롯이라 그것도
함께 밀어야 합니다.

**그런데 그걸로도 부족했습니다.** 슬롯과 점프를 다 맞췄는데도 적 턴 피격 대사에서
`카즈야Lケ「안맞아!」` 처럼 색인 바이트가 글자로 찍혔습니다 — 대사 레코드로 2 바이트
어긋나게 진입한 것입니다. **세 번째로 위치에 의존하는 무언가**가 더 있고, 아직 못
찾았습니다. 그래서 이름 확장은 보류하고 **길이가 같은 치환만** 씁니다.

이 결함이 v0.99e·f 두 릴리스에 들어간 채 나갔습니다. v0.99e 때 확인한 것은 필살기 대사
한 줄이었는데 그걸로 안전하다고 일반화한 탓입니다. **길이를 바꾸는 변경은 진입 경로마다
따로 확인해야 합니다.**

**같은 블롭이 RAM에 두 번 올라올 수 있다.** 전투 대사 블롭은 `0x80107B8C` 에 한 번,
전투가 시작되면 BATTLE 오버레이가 **한 번 더 풀어** `0x801A6878` 에 올립니다. 무기 구호는
1차를, 화자 이름과 컷인 대사는 2차를 읽습니다. 2차 해제본은 블롭 55,353 B 만 담으므로,
위에서 연 확장 구간은 **1차를 읽는 레코드에만** 쓸 수 있습니다. 이걸 모르고 이름표를
확장 구간에 옮겼다가 전투 대사가 글자 쓰레기가 됐습니다.

**바이트 검증은 화면 검증이 아니다.** 그 이름표를 블롭 안에서 늘리고 안쪽 슬롯 27개를
이동 전/후 바이트열로 직접 대조해 통과시켰는데도, 실기에서는 대사가 사라지고 **초상화까지
깨졌습니다.** 그 표는 이름뿐 아니라 초상화 인덱스까지 담고 **항목의 위치가 곧 의미**였습니다.
슬롯은 그 표를 읽는 유일한 경로가 아니었습니다.

**같은 오프셋이라도 사본마다 다른 데이터다.** 그 확장을 세 번째 사본(C_BEFCT)의 같은
오프셋에도 넣었다가 맵 대화를 통째로 날렸습니다. 검증한 것은 오버레이 쪽이었지 이쪽이
아니었고, 두 자리는 전혀 다른 내용이었습니다. **검증한 자리만 검증된 것입니다.**

**게이트가 자기 자신을 검증하면 안 된다.** 레코드를 옮기며 별칭을 다시 잇는 변경에서,
게이트가 기대값을 같은 재매핑 로직으로 만들면 틀려도 양쪽이 똑같이 틀려 통과합니다.
실제로 "설명 안 됨 0" 으로 통과한 빌드가 실기에서 대사가 반토막 났습니다. 지금은 옮기기
**전** 슬롯이 가리키던 바이트열과 옮긴 **후** 바이트열을 직접 대조합니다
([`tools/mbankb_nametable.py`](tools/mbankb_nametable.py)).

**스크립트가 레코드 사이를 상대 거리로 건너뛴다.** 맵 스크립트에는 s16 상대
오프셋 점프가 있어서, 번역문을 넣으며 레코드를 다시 채우면 그 점프가 엉뚱한 곳을
가리킵니다. 전함 발진이 통째로 멈춘 원인이었습니다. 그 뱅크만 **원본 배치 그대로**
내보내고 역문은 원문 길이 안에서 제자리 치환하도록 풀었습니다. 덤으로, 표 슬롯이
가리키지 않고 **점프로만 도달하는** 레코드 16개를 찾았습니다 — 추출조차 안 되던
자리라 여태 일본어로 떠 있었습니다.

**조용한 누락이 기본값이다.** 번역이 빌드에서 빠져도 아무도 알려주지 않습니다.
그래서 모든 단계에 "원본 그대로이거나, 역문과 정확히 일치하거나" 를 강제하는 게이트를
두었습니다. 실제로 이 게이트가 재뱅커 버그 두 개와 원장이 통째로 건너뛴 6줄을 잡아냈습니다.

## 저장소 구조

```
tools/    역공학·빌드 도구 (Python 100개)
docs/     기술 문서 — 포맷 분석, 빌드 절차, 작업 기록
dist/     배포용 xdelta 패치와 설치 안내
```

### 도구 몇 가지

| 파일 | 하는 일 |
|---|---|
| `lzb.py` / `lzb_encode.py` | 게임의 LZSS 계열 압축 해제·재압축 |
| `isotool.py` | Mode2/2352 디스크 이미지 읽기·파일 목록 |
| `patch_image_reloc.py` | 파일 재배치·확장을 반영한 이미지 재작성 |
| `mb_rebank4.py` | M_BANKS 재뱅킹 (표마다 독립 블록) |
| `mb_alias.py` | 레코드 안쪽 별칭을 역문의 같은 구조 자리로 이동 |
| `hangul_font.py` | 16×16 한글 글리프 생성 |
| `reinsert_build.py` | D_NAMES 재삽입 (공유·정렬·폭 검사) |
| `build_battle_ko.py` | 오버레이의 안 읽히는 구간을 대사 자리로 |
| `mbankb_jumpfix.py` | 화자 이름을 늘리고 상대 점프 s16 보정 |
| `verify_*.py` | 각 단계의 게이트 |

### 빌드 순서

원장을 고친 뒤:

```
mb_rebank4.py --tr → verify_mb_ledger.py / verify_mb_rebank4_tr.py
  → reinsert_build.py → verify_reinsert.py
  → build_staydat_ko.py → build_cdemog_ko.py
  → build_mbankb_ko.py → build_cbefct_ko.py
  → patch_image_reloc.py → patch_image_resize.py
```

번역 원장(`translation/`)은 게임 원문 스크립트를 통째로 담고 있어 저장소에
포함하지 않았습니다. 도구는 원장이 있어야 돌아갑니다.

## 알려진 제한

- 이름 선택 목록에 일본어 가나가 섞여 있습니다. 원문이 짧아 한글로 줄일 수 없는
  항목(グレース·ミーナ·リン 등)은 원문 그대로 두었습니다. 이름은 직접 입력할 수 있습니다.
- 표 밖 전투 대사는 자리를 못 옮깁니다(게임이 다른 경로로 색인합니다). 칸이 좁은 몇몇
  줄은 여전히 줄여 썼습니다.
- 전투 화면의 화자 이름 일부(`一矢` `ギャリソン` `洸`)는 원문입니다. 이름을 늘리면
  인접 대사의 진입이 어긋나는데 그 원인을 아직 못 찾았습니다. 길이가 같은 치환
  (`豹馬`->효마, `万丈`->반죠)만 적용했습니다. 맵 대사에서는 모두 한글로 나옵니다.
- 발진 대사는 칸이 1 B 도 안 남아, 기체 이름 뒤 공백을 넣으려고 느낌표를 하나 줄였습니다.

## 라이선스와 범위

도구와 문서는 자유롭게 쓰셔도 됩니다.

패치는 원본 디스크에 적용하는 **차분 파일**입니다. 게임 데이터는 들어 있지 않습니다.
