# 커스텀 텍스트 인코딩 계약

상태: **글리프 ID·제어 인수 길이 확정 / 문자표 교차 버전 검증 중**

## 소비자 증거

`MAP.LZB` 해제물 SHA-256 `2ca28fd267f6521efced7c677cedd41a8334f706ded141495389a6114d28ede7`의 해제 오프셋 `0xB3F0`–`0xB438`에서 주 디코더를 확인했다. Capstone 5.0.7로 MIPS R3000 little-endian 명령을 해석했고, `tools/analyze_structures.py`는 핵심 명령어 word를 독립적으로 재검증한다.

```text
byte < F0: glyph_id = byte
F0 <= byte < F6:
    trail = *stream++
    glyph_id = ((((byte + 1) << 8) & 0x0F00) + trail)
byte >= F6: control dispatch
```

같은 해제물 오프셋 `0x4D378`–`0x4D494`의 두 번째 소비 루틴도 `< F6` 분기와 동일한 확장 글리프 산식을 사용한다. 따라서 데이터 빈도만으로 추정한 계약이 아니라 두 소비자가 일치하는 계약이다.

| `F0 xx` | 확장 글리프 page 1 | ID `0100`–`01FF` | 확정 |
| `F1 xx` | 확장 글리프 page 2 | ID `0200`–`02FF` | 확정 |

| `F4 xx` | 확장 글리프 page 5 | ID `0500`–`05FF` | 확정 |
| `F5 xx` | 확장 글리프 page 6 | ID `0600`–`06FF` | 확정 |

표현 가능한 글리프 코드는 1,776개이며 ID 공간은 `0000`–`06FF`의 1,792칸이다. `00F0`–`00FF` 16칸은 저장 글리프 코드로 직접 생성되지 않는다.

## 제어 인수와 구조적 FF

같은 PS1 계열 엔진을 분석한 공개 프로젝트 `snake7594/srwcb-korean-patch` commit `9883a43ebe44dafaeba340ef6d8f6af54b9cf3c7`의 소비자 추적 결과는 위 인수 길이를 사용한다. 이 규칙은 본 타깃에서도 `FD FF FF`, `FE FF`처럼 인수에 `FF`가 들어간 뒤 더 뒤에 실제 종단이 나오는 308개 `D_NAMES` 레코드로 교차 검증됐다.

따라서 `bytes.find(FF)`는 유효한 문자열 파서가 아니다. 기존 raw manifest의 4,090개 포인터/ID는 유지되지만, 308개 원문은 조기 종료되어 있었다. `tools/analyze_structures.py`를 고쳐 토큰 단위로 실제 종단을 찾은 뒤 `_work/analysis/dnames_raw_manifest.tsv`를 재생성했다.

## 문자표 후보

Complete Box 프로젝트의 reviewed mapping SHA-256 `791bb9ff6f0e73fe217bf5db9e2c9a11cc7012f6c50226ef776725fc88e16af9`에서 ID `0000`–`06FF`를 적용하면 본 타깃의 로봇명·파일럿명·무기명·지형명·시나리오명이 문맥에 맞는 일본어로 복원된다. 예: `流竜馬`, `ビームサーベル`, `発端`. 이는 두 작품의 글리프 사전 앞 1,792칸이 사실상 계승됐다는 강한 증거다.

- `D_NAMES`에서 사용된 글리프 ID는 969종이다.
- donor 표와 target-native override를 합쳐 966종을 복원한다. 현재 미해결 표시는 아이콘성 `00C`, `0EA`, `0ED` 3종, 54회다.
- low glyph `005`는 donor의 `√`가 아니라 본 타깃의 명칭 문맥상 `ν`(`νガンダム`)로 override한다.
- target-native 비트맵과 반복 문맥이 함께 닫힌 `100=兜`, `348=汎`, `3FF=전각 공백`, `515=桜`, `562=魂`, `596=遷`, `5C2=閥`, `5F7=慕`, `646=愾`, `649=毅`, `652=候`, `667=惨`, `698=逐`, `6FE=▲`도 타깃 override로 고정한다.
- donor OCR/문맥 검토표는 파생 보기일 뿐이다. raw bytes와 glyph ID가 계속 권위 원본이다.

파생 일본어 보기는 `_work/analysis/dnames_decoded_candidate.tsv`이며 `tools/decode_dnames.py`로 재생성한다.

## M_BANKS 적용 범위

MAP의 `M_BANKS` 소비자는 61개 은행마다 `0x200`바이트의 고정 포인터 표를 캐시하고, `(bank, slot)`이 선택한 bank-relative 위치부터 `0x400`바이트를 읽는다. 56개 non-null 은행의 14,336 슬롯 중 14,105개가 이 읽기 창 안에서 위 토큰 규칙에 맞는 구조적 `FF`를 가진다. 51개는 파일 밖을 가리키는 명백한 미사용 후보이고 180개는 파일 안이지만 창 안에 종단이 없다. 54개 레코드는 64KiB 은행 경계를 넘으므로 은행 끝을 문자열 한계로 사용하면 안 된다.

스크립트의 16-bit 메시지 선택자는 `selector = 0x9000 + bank*0x100 + slot`이고, 소비자는 이를 다시 상위 바이트 은행과 하위 바이트 슬롯으로 분해한다. 이벤트 표시 레코드의 raw 필드는 bit 15를 상태 플래그로 겸용하므로 `raw & 0x7FFF`를 먼저 적용한다. 후보 manifest의 `selector_hex`는 이 계약에서 직접 산출한다.

`FB aa bb`는 `aa | (bb<<8)` selector를 만든다. 정적 값이 `0x9000` 이상이면 같은 `M_BANKS` 경로로 재진입한다. 인수에 `FF`가 들어가는 경우는 런타임 치환 경로이므로 원시 인수를 보존하며, 값 공급원이 확인되기 전에는 정적 대상으로 가정하지 않는다.

`_work/analysis/mbanks_candidate_manifest.tsv`는 모든 런타임 슬롯을 보존하되, `0x400` 안에서 구조적 `FF`가 확인된 슬롯만 파생 일본어를 기록한다. 포인터가 텍스트 중간이나 비텍스트 데이터에 닿는 미사용 슬롯도 있으므로 이 파일은 번역 원장이 아니다. 증명된 `SC_00/04/05` VM entry/fallthrough 참조 1,550개와 직접/수식 대상 74개를 합친 현재의 소비자 한정 closure는 `_work/analysis/mbanks_live_closure.tsv`의 1,624개다. 전부 토큰 종단·매니페스트 해시 일치를 통과했으나 전체 CFG와 동적 루트는 계속 열린 범위다.

이 closure는 1,589개의 고유 raw 레코드, 1,142개의 고유 원문 글리프 ID를 사용한다. `D_NAMES` 전체의 969종과 합집합은 1,316종이므로, 모든 현재 원문 글리프를 보존한다는 보수적 가정에서는 1,776개 표현 가능 ID 중 460개가 남는다. 이는 **한글 수요량이 아니라 용량 기준선**이며, 최종 한국어 코퍼스와 일본어 보존 정책이 정해진 뒤 다시 계산해야 한다.

## 현재 추출 정책

- `F0`–`F5`와 다음 바이트는 분리할 수 없는 하나의 글리프 코드로 보존한다.
- `F6`–`FE`는 위 인수 길이로 토큰화하고 opcode와 인수를 원시 바이트로 보존한다.
- `FF` 이후 바이트는 같은 문자열에 포함하지 않는다.
- target-native 글꼴 저장/소비 경로는 확정됐지만, 타깃 문자표의 미해결 ID와 재삽입 왕복이 닫히기 전에는 번역하지 않는다.

## 무변경 코덱 왕복

`tools/text_codec.py`는 모든 1,776개 표현 가능 글리프 ID와 제어 opcode/인수를 손실 없이 토큰화·재인코딩한다. `tools/verify_text_roundtrip.py` 검증 결과는 `_work/analysis/text_roundtrip_report.json`에 기록한다.

- `D_NAMES`: 4,090 occurrence / 2,422 unique raw records, mismatch 0.
- `M_BANKS`: 14,105개의 `0x400` 창 내 토큰 종단 occurrence / 11,733 unique raw records, mismatch 0.
- 파일 밖 51슬롯과 창 내 종단이 없는 180슬롯은 레코드로 가장하지 않고 왕복 대상에서 제외한다.

이 통과는 **기존 바이트의 토큰 왕복**만 증명한다. 번역문 길이 증가, 포인터 재배치, 라이브 슬롯 판정, 컨트롤 의미, ISO 재삽입은 별도 게이트다.

`SLPS_001.96` 파일 오프셋 `0x20B00`(RAM `0x800E0300`)에는 BIOS A0 함수 `0x51` 래퍼가 있고 `MOVIE.LZB` 해제 오프셋 `0x7258`이 이를 호출한다. 그러나 주 MAP 텍스트 렌더러는 STAYDAT `0x36800` 디스크립터의 세 내장 글꼴 은행을 직접 소비한다. 따라서 BIOS KROM 경로는 영화/별도 효과 경로로 유지하며 주 대사 폰트로 간주하지 않는다. 정확한 글꼴 계약은 `FONT.md`를 따른다.
