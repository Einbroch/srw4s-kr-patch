# LZB 압축 — 포맷과 인코더 (2026-08-24)

## 왜 이 문서가 생겼나

이 프로젝트는 시작부터 **"LZB 인코더가 없으니 압축 파일 재삽입 금지"** 를 원칙으로 삼았다
(`HANDOFF` 2026-08-20 compression). M_BANKS 주소 계산을 바꾸려면 그 코드가 들어 있는
`MAP.LZB` 를 고쳐야 해서, 인코더를 새로 만들고 **실기에서 검증**했다. 금지는 해제됐다.

## 포맷

디코더 정본은 `tools/lzb.py` (RAM `0x800C345C`, EXE 파일 `0x3C5C` 의 충실한 이식).

```
1            리터럴 바이트
0 1          긴 매치: 빅엔디언 W 2바이트
               off = (W >> 3) - 0x2000        (-8192 .. -1, 항상 음수)
               n   = W & 7
               n>0 -> len = n + 2             (3..9)
               n=0 -> 다음 바이트 L
                      L == 0 이면 스트림 종료
                      아니면 len = L + 1      (2..256)
0 0          짧은 매치: 2비트 n, 다음 바이트 off = b - 0x100  (-256..-1), len = n + 2 (2..5)
```

### 함정: 플래그와 데이터가 같은 스트림에 섞인다

디코더는 **비트 버퍼가 비는 순간 그 자리의 바이트를 플래그 바이트로 집어간다.**
플래그를 따로 모아 두고 데이터를 잇는 구조가 아니다. 작성기도 비트가 필요할 때
**현재 출력 위치에 한 바이트를 예약**하고 채워 넣어야 한다.
처음에 플래그를 별도로 모으는 방식으로 짰다가 첫 매치에서 바로 깨졌다.

비용(비트): 리터럴 9 / 짧은 매치 12 / 긴 매치 18 / 긴 매치+L 26

## 인코더

`tools/lzb_encode.py` — 3바이트 해시 체인 매치 탐색 + lazy 평가.
비트당 이득(`len*8 / cost`)이 가장 큰 매치를 고르고, 다음 자리가 더 유리하면 리터럴로 미룬다.

## 검증

`tools/verify_lzb_roundtrip.py` — 원본 4개를 풀었다 다시 압축해 **해제물이 같은지** 본다.
크기가 원본보다 커도 무방하다(파일을 옮기면 된다). 내용 동일이 조건이다.

| 파일 | 원본 | 해제 | 재압축 | 배율 |
|---|---:|---:|---:|---:|
| MAP.LZB | 155,629 | 373,128 | 161,041 | 1.03 |
| MOVIE.LZB | 21,148 | 32,924 | 22,021 | 1.04 |
| BTT/BATTLE.LZB | 195,439 | 388,880 | 201,815 | 1.03 |
| BTT/M_BANKB.LZB | 33,362 | 55,353 | 34,409 | 1.03 |

**실기 검증(2026-08-24)**: 내용을 바꾸지 않고 `MAP.LZB` 만 재압축해 넣은 디스크로
타이틀 -> 세이브 로드 -> 스테이지 2 진입 -> 적 증원까지 정상 확인.
`MAP.LZB` 는 76 -> 79섹터가 되므로 `MOVIE.LZB` 를 꼬리로 옮겨 자리를 낸다.
