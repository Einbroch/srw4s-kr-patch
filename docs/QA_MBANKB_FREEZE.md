## 릴리스 차단 항목

### 1. §8.3.1 — 외부 참조 완전성이 증명되지 않은 상태의 sub-entry 재배치

`HIDDEN_MOVE` 는 표 밖 레코드를 블롭 끝으로 옮기고 `{C:01}{A}` 자기상대 참조만 다시
가리킨다. 근거는 "블롭 안에서 그 레코드를 가리키는 참조를 전수로 찾았다"이다.

표준이 금하는 바로 그 추론이다 — **런타임이 오버레이 코드 안의 상수/파생 주소나
별도 생성 테이블을 쓸 수 있다.** MAP/BATTLE 오버레이(각 0x80106380 적재)를 이 관점으로
훑은 적이 없다.

실제 실패 2회:
* 27건 이동 (참조 344곳 추가) -> 적턴 병사 전투 진입에서 글자 깨짐 + 멈춤
* 16건 이동 (참조 295곳)      -> 같은 자리에서 인용부 빈칸

기계 쪽은 전수로 결백 확인 (재현 조사 불필요):
표 밖 바이트 기록 0건 / 가짜 표 0건 / 표 시작·u16 정렬 어긋남 0건 /
옮긴 레코드 겹침 0건 / 참조 4,521개 중 범위 밖·빈 레코드 대상 0개.

**조치:** 참조 완전성이 증명될 때까지 `HIDDEN_MOVE` 를 신규 확대하지 않는다.
현재 34건(마지막 런타임 PASS 집합)을 floor 로 고정한다.

### 2. §8.8.4 — 물리 중복 소비자 미동기화

같은 M_BANKB 텍스트를 **두 벌**이 소비한다.

| 사본 | 경로 | 크기 | 내용 |
|---|---|---:|---|
| 1 (2차 해제본) | `/BTT/M_BANKB.LZB` 해제 | 58,689 B | 제자리 + 재배치 149 + 이동 50 |
| 2 (전투측) | `/BTT/C_BEFCT.BIN` 내부 0xA8 | 55,353 B | **제자리 번역만** |

앞 55,353 B 를 대조하면 **3,152 바이트가 서로 다르다.** 사본 2 는 크기가 고정이라
재배치·이동을 구조적으로 담을 수 없다. 표준은 "base table 과 expanded/merged table 이
따로 있으면 모두 동기화한다"를 요구하는데, 지금 구조로는 동기화가 불가능하다.

**조치:** 어떤 대사가 어느 사본에서 소비되는지 확정하기 전에는 이동 대상을 늘리지 않는다.
(비트15 선택 -> `mbankb-two-copies`)

## 주의 항목 (차단은 아님)

### §8.4.1 — decoded size 는 런타임 계약이다
블롭 해제 크기 55,353 -> 58,689 (+6.0%). 압축본은 33,362 B / 17섹터로 **retail 과 동일**
(§8.4.4 축소 없음 PASS). 해제 크기 증가의 근거는 실기 프로브 1회뿐이다
(`bloblimit.lua`: 블롭 뒤 base+65,198 까지 아무도 안 씀, 정적 할당표의 0x801B6800 과 일치).
allocator/loader 에 전달되는 크기 자체는 확인하지 못했다.

### §8.5 — 물리 레이아웃: 회귀 없음
이미지 섹터 166,731 동일. 이번 변경으로 LBA 이동 0, 크기 변경 0, 겹침 0.
(누적 패치에는 꼬리 재배치 15개·크기 변경 3개가 있으나 모두 이전 런타임 PASS 이력.)
`CMSONG.DA`/`NULL.DA` 가 이미지 밖으로 잡히는 것은 **원본도 동일** — CD-DA 트랙, 오탐.

§9.1 재현 조건: **간헐 재현.** 같은 RC `171d4190383c0a35`, 같은 조건에서 3회 시행 결과가 갈렸다.

| 회차 | 장면 | 결과 |

| 2 | 적 병사 vs 점보트3 전투 진입 | **멈춤** |
| 3 | 같은 전투 | **정상** |

실기 프로브 2종으로 확인한 것:

* `hangpc.lua` — 정상 회차의 pc 도수분포에 갇힌 자리 없음. 분기표·참조 전수 정상.
  (한 프레임에 같은 자리 4회 진입은 `{N}` 뒤 이어지는 줄이라 정상.)

### 이것이 바꾸는 것

간헐 결함이면 **런타임 통과 1회로 안전을 증명할 수 없다**(§9.4). 따라서
* 이분 탐색이 신뢰할 수 없다 — "통과"가 운일 수 있다.
* 현재 canonical(이동 34건)도 같은 부류의 위험을 안고 있을 가능성을 배제할 수 없다.
  다만 플레이 이력이 훨씬 길어 증거는 더 많다.

### 조치 (적용 완료)

오버레이 코드 안의 오프셋 상수(적중 6% < 대조군 8%) / 블롭 크기(프로브 실측).
